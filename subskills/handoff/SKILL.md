# Handoff — 会话交接与经验沉淀

> `super-memory` 的 handoff 子命令（写入端）。写"中期交接记忆" `.ai/HANDOFF.md`，并把已验证的通用内容升档到"长期项目记忆" `.ai/knowledge/`。接手项目 / 继续上次会话 → 走 `intake`。
> 本文件由父级用 Read 加载，不是独立 skill；工具授权看父级 frontmatter。

## 核心铁律

1. **先读后改** — 改任何文件前完整读过，理解现有逻辑与历史决策
2. **代码优先** — 文档、记忆、描述与实际代码不一致时，以代码为准
3. **验证优先** — 陈述事实前先跑工具，不凭记忆回答
4. **不懂就说** — 不确定的标 `[Q]`，禁止编造
5. **最小改动** — 只做任务必需的修改
6. **差异必报** — 发现交接信息、历史记忆与实际不符，第一时间指出并更新
7. **知识必沉** — 典型问题、重要决策、通用模式必须同步进长期库
8. **闭环更新** — 会话结束必须完成交接更新与知识沉淀

## 置信度码（句首必带，全大写方括号）

| 码 | 含义 | 成立条件 |
|---|---|---|
| `[V]` | 已验证 | 代码落地 + 通过完整测试，结论经代码核验 |
| `[W]` | 进行中 | 逻辑部分闭环，未经全量验证 |
| `[Q]` | 待确认 | 观察到的现象或推导结论未实证 |
| `[R]` | 有风险 | 涉及核心模块或公共依赖，存在兼容副作用 |
| `[F]` | 已固化 | 已沉淀进 `.ai/knowledge/`，稳定可复用 |

写每条前自问：这轮真跑过验证命令吗？跑过才准 `[V]`，没跑过只能 `[Q]`。

## 流程 A：写入端

### A1. 定位

`.ai/` 在**项目根目录**。跨项目工作时，每个被改动的项目各自一份 HANDOFF，不合并写。

```bash
ls -la .ai/ .ai/knowledge/ 2>/dev/null
find . -maxdepth 2 -iname "HANDOFF.md" -not -path "*/node_modules/*"
```

三种情况分流：

- **没有 `.ai/`** → 建目录，按 `../../references/handoff-template.md` 的十一节（§0 快照 + 十节编年）写首版。
- **有 HANDOFF 但形状不同**（例：FDE 那份是自定义 8 节）→ **只做对齐**：检查缺哪几个必需节，缺的补上（补 §0 快照时从最末节提炼当前状态，注明提炼自哪节），已有的节保留原编排与原文，**不重排、不改写别人写好的段落**。
- **文件 mtime 晚于本次会话开始** → 另一个会话正在写，先比对内容差异再决定合并方式，不得整体覆盖。

### A2. 更新各节（模板见 `../../references/handoff-template.md`）

**先刷新 §0 当前快照**（目标 → 需求与约束 → 关键决策 → 状态三态 → 下一步动作 → 相关文件 → 关键上下文），再追加/更新编年节：会话概览 → 已完成 → 进行中与断点 → 已知问题与技术债 → 本次经验沉淀 → 长期记忆同步说明 → 下一步行动 → 运行与验证 → 操作禁区 → 版本记录。

写入质量七条硬要求：

- **精准锚定**：每条都带具体文件路径、函数、代码位置或 commit；空泛描述不收
- **根因导向**：问题记录除了解法必须写根因与推导过程，能举一反三
- **场景边界**：可复用经验必须标"适用于/不适用于"
- **客观事实**：只记已发生、已验证的；猜测标 `[Q]`
- **进度可扫读**：§0 快照（无 §0 的旧文档则 §1/§3/§7）写满写实，接手者不读全文即可回答「到哪了/停在哪/下一步」；状态三态（已完成/进行中/阻塞）一个不缺，禁止只留指针
- **快照即头部**：§0 是唯一的"当前"入口——每次追加先刷新它（只放当前，详情指到编年节）；压缩保全（PreCompact）时可只刷新 §0 + §3。追加式文件的最新在末尾，§0 过期 = 接手误判的头号来源
- **去冗余化**：已进长期库的通用内容，HANDOFF 里只留索引指向，不抄全文

### A3. 升档到长期库

判据：**这条内容换一个模块、换一个场景还用得上吗？** 用得上才升，用不上留在 HANDOFF。

```
[V] 或 [F] 且通用  → 写入 .ai/knowledge/ 对应分类，HANDOFF 里改为索引 + 标 [F]
[V] 但只在本模块  → 留在 HANDOFF
[W] [Q] [R]      → 一律不升档（长期库只收已验证事实）
```

目录**按需创建**：只建本轮真有内容的分类（五分类语义见 `../../references/knowledge-tiers.md`），不预铺空文件、不为了凑骨架写空条目。

**写入前先巩固**：grep 相似旧条目后按**四操作**四选一并写明判定——ADD 新建 / UPDATE 改旧条目保留原 ID / SUPERSEDE 旧条目标 `[已失效]`+替代指针不删 / NOOP 等价不写（详见 `../../references/knowledge-tiers.md`）。新条目入库前必须检索相关旧条目，双向写 `**Related**` 互链；条目带 `**生效**`/`**记录**` 双时间戳。

### A4. 版本记录只追加

第十节每条记录含：更新时间（绝对日期）、更新主体、核心变更摘要、本次沉淀的知识标签。

**禁止修改或删除历史条目**——只能追加，或按 A5 把失效条目的置信度降级并标注原因。

### A5. 验证（不许跳过）

```bash
grep -nE "^## " .ai/HANDOFF.md                                        # 节齐不齐（§0 + 十节）
grep -cE "\[[VWQRF]\]" .ai/HANDOFF.md                                  # 带置信度的行数
grep -rcE "\[[VWQRF]\]" .ai/knowledge/ 2>/dev/null | awk -F: '{s+=$NF} END{print "长期库置信度行数:", s+0}'
grep -rnE "\[(V|W|Q|R|F)\]" .ai/HANDOFF.md | grep -oE "\[[VWQRF]\]" | sort | uniq -c   # 各码分布
```

统计正则必须能同时命中三种位置：**句首行首**（`[V] …`）、**bullet 后反引号内**（`` - `[V]` … ``）、**字段行中部**（`**置信度**：[V]`）。改模板或改正则任一边，都必须拿另一边格式的黄金样本实测命中一次，不许只看命令"长得对"——`^\[[VWQRF]\]` 这种行首锚定对模板条目实测恒为 0。

然后**逐条核验 `[V]`**：条目里提到的文件/函数/commit 用 `ls`、`grep`、`git log` 各确认一次。核验不过的当场降级为 `[Q]` 并写明差异。摘要里报实测数字，不报"已更新"。

## 接手读取（已迁出）

接手项目 / 继续上一个会话 / "看看现在到哪了" → 走 **`intake`** 子命令：记忆文档探测、真值核验、接手简报全在那边；本文件只负责写入端。

## 禁区

- 禁止修改历史交接记录与长期库归档内容（只能追加、降级、补注）
- 禁止把未验证的推断标 `[V]`
- 禁止把敏感信息（密钥、token、真实环境变量值、用户数据）写进 HANDOFF 或 knowledge
- 禁止用模式匹配/时间范围批量删交接记录；清理只按本次会话自己当场记下的具体条目 id
- 禁止把 HANDOFF 写成流水账：单次调试过程、中间尝试、局部变量属于短期会话记忆，不落盘
