# Intake — 接手项目与阅读交接

> `super-memory` 的 intake 子命令。接手存量项目、继续上次会话、新会话开工的读取入口；也负责新项目初始化。
> 本文件由父级用 Read 加载，不是独立 skill；工具授权看父级 frontmatter。

## 两个场景

| 你在做什么 | 走哪条 |
|---|---|
| 接手存量项目 / 继续上一个会话 / 新会话开工 / "看看现在到哪了" | **场景 A**：接手读取（A1–A6） |
| 启动新项目（无交接可读，或用户说"初始化"） | **场景 B**：初始化骨架 |

置信度统一用 `[V][W][Q][R][F]`（无 emoji），全义与写入端铁律见 `../../subskills/handoff/SKILL.md` 开头。

## 场景 A：接手读取

### A1. 项目定位与全局扫描

先输出**画像四项**：核心业务定位与使用场景 · 技术栈（语言/框架/依赖/数据库/部署） · 所处阶段（原型/开发中/测试/上线/维护） · 根路径与一级目录。

执行：读 `README.md` 与配置文件（`package.json`/`pyproject.toml`/`pom.xml` 等）→ 遍历两级目录 → `git log -10` 看最近提交 → **列最近修改文件 Top10（源码+文档，`ls -lt`/`find -newermt`）＝活跃开发区**——未提交的开发只在文件 mtime 显形，git log 看不见 → 检索 AI 协作文件目录（按 A2 的探测清单）。

### A2. 记忆文档探测与按角色读

**记忆文件在哪个目录、叫什么名字，一律现场探，不按惯例假设。** 按 `../../references/intake-memory-discovery.md` 清单探测容器与文件名模式（含中文/日期变体），**排除** `src/`、`tests/`、第三方目录同名误报。

命中文件按**角色**分类后按优先级读（判定线索见 discovery 文件）：

**先辨文件形态**：快照式（覆盖重写）从头读；**追加式**（编号递增）最新在**末尾**——先 `tail` + 节清单全列（不许 head 截断）；含 **§0 当前快照**以其为准并核对末尾最新节，旧式无 §0 以末尾为准。

**读记忆 = 全面分析，不是抽查**：结构级（节/日期清单全文枚举建时间轴，答不出"覆盖哪天到哪天"＝读得不全）→ 内容级（最新节全文，其余扫标题日期；"无未闭环工作"必须出自**最末节**）→ 多源交叉（同角色多份文档全读互证，只读一份不下结论）。三层次操作细节见 `../../references/intake-memory-discovery.md`。

**检索纪律（找记忆时）**：单轮 grep 不够——⓪ **先定库**（`search.py --auto` 一步枚举项目位+宿主位全扫；或手动逐库）；① 换词三连（中/英/同义词，如 错误↔踩坑↔failure）；② 补搜 Tags、路径片段、日期、ID 前缀；③ 多词查询走 `python <skill目录>/scripts/search.py "词" --root <库>`。全部库×全部词空才可判"无"。同义词对与实测案例见 discovery。

1. 交接（HANDOFF/HANDOVER/交接*）— 进度、断点、下一步、禁区
2. 进度（PROGRESS/进度*/dev-state）
3. 概览（PROJECT_BRIEF/README/项目记忆）
4. 架构（ARCHITECTURE/MAP）
5. 决策（DECISIONS）
6. 任务（TASKS/TODO）
7. 规范（coding_standards/context/*、AGENTS.md、CLAUDE.md）
8. 踩坑（known_issues/LEARNINGS/踩坑记录）

读完声明："记忆文件读取完毕（列出实际读到的文件），全部结论待代码核验。" 命中长期库条目时先核对"适用于/不适用于"边界，越界不复用。宿主记忆库按 `../../references/memory-addressing.md` 另行定位读取（管跨会话偏好，不替代项目交接）；`.learnings/` 扫待处理项。

### A2b. 分散繁杂 → 整理

同一职能 ≥2 份或跨容器散落 → 输出**记忆文件地图**（角色→路径→置信度→是否最新）+ 两种整理模式：① **索引归位**（默认：立/刷新入口索引指向散落文档，**不动原文件**）；② **物理归并**（仅用户确认：移动/合并，源文件走 `.tmp/` 隔离、清理引用——规范复用 `../../references/delete-review-template.md`）。**整理阶段禁止擅自移动文档**——接管时乱动比散落更糟。

### A3. 真值核验

建目录工作树（按功能模块分组，≤3 层，标注入口/主流程/配置位置），对记忆文件的关键断言逐项核验：

| 核验项 | 验证方法 |
|---|---|
| 接口清单 | 检索路由定义/注解，与文档逐一比对 |
| 数据模型 | 读 schema / ORM 定义，与文档字段比对 |
| 环境变量 | 读 `.env.example` 与各环境配置，与文档比对 |
| 核心函数 | 读关键入口函数，确认参数/返回值/调用链 |
| 构建命令 | 从脚本配置核对启动、构建、测试命令 |
| 依赖版本 | 查锁文件确认实际版本 |

输出：一致项 / 差异项（附 `file:line`）/ **重大差异高亮**（架构不符、接口废弃级）。差异以代码为准。

### A4. 进度确认

从 git 与文件系统核对：最近提交的改动与时间 · 已完成并通过测试的功能 · 开发中断点与当前进度 · 已知 bug / 技术债 / 阻塞 · 下阶段优先级。

**git log 只覆盖已提交工作**，配齐三件：`git status`（未提交开发不在 log）· `git branch --show-current`（活跃线）· `git log <最新tag>..HEAD --oneline | wc -l`（发布后开发量）。追加式交接的最末节与记忆位当日文件交叉印证，冲突以末尾为准。

**新鲜度三角（差异必报）**：记忆自述"最后更新" ↔ git HEAD 日期 ↔ 源码最新 mtime——对不齐＝记忆漂移，以文件系统为准；源码热点区与记忆所述开发重点不符同属差异。

### A5. 接手简报（输出）

1. **差异表**：记忆 vs 实际（一致/差异，每条附 `file:line` 证据）；记忆过期 → 降置信度并注明，不改历史。
2. **简报六要素**：项目定位与技术栈 · **进度三问直答**（到哪了/停在哪/下一步） · 已发现的差异 · 修改边界与禁区摘要 · 准备执行的第一个动作 · 置信度图例。
3. **记忆质量反馈**：缺锚点/无验证命令/过时/分散/无索引 → 列入待修正项；修正走写端或整理（A2b）。
4. `[Q]`/`[R]` 项优先处理，再按下一步行动清单开工。

### A6. 工作规范（接手后遵行）

- 修改边界：可改=业务逻辑/功能/Bug/文档；谨慎=核心框架与公共工具（先查调用方）；禁止=生产配置密钥、他人边界模块、CI/CD（未授权）。
- 验证顺序：lint → 类型 → 单测 → 集成 → 回归；新功能配测试。
- 最小必要变更：不做无关重构、不擅自升依赖、不改接口契约。

## 场景 B：新项目初始化

判据：目录没有 `.ai/` 且确认是新项目，或用户明确说"初始化"。

按 `../../references/intake-scaffold.md` 生成骨架：**必备 3 件**（`.ai/HANDOFF.md` 首版十节 · `.ai/knowledge/README.md` 索引 · `docs/wiki/index.md`）先建；可选项（PROJECT_BRIEF/ARCHITECTURE/TASKS/VERIFICATION/context/* 等）**按项目规模选建，不预铺空分类空子目录**；每个文件=标题+一行用途+占位，不写空节全文。

完成后接线：开发结束/暂停 → handoff；错误与纠正 → capture；阶段性整理 → neat。

## 衔接与禁区

衔接：写交接 → handoff；错误/纠正 → capture；全库审查 → neat；跨会话偏好 → save。

禁区：

- 禁止采信记忆文件不核验就开发
- 禁止跳过断点说明重做已完成的工作
- 禁止在接手阶段改写历史记录（只能追加、降级、补注）
- 禁止越界复用（不核对"适用/不适用"就用旧解法）
- 禁止整理阶段未经确认移动/合并记忆文档
- 禁止初始化时预铺空分类、空子目录（与 knowledge-tiers"按需创建"对齐）
- 禁止把未验证的推断标 `[V]`
