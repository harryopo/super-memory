# HANDOFF.md 模板（§0 快照 + 十节编年）

新建项目用整份。已存在 HANDOFF 的项目**只补缺失的必需节**（标 ★ 的七节），保留原编排，不重排、不改写他人段落。**追加新会话时：先刷新 §0 快照，再追加编年节。**

每条内容句首带 `[V]`/`[W]`/`[Q]`/`[R]`/`[F]`，含义见 `../subskills/handoff/SKILL.md`。

```markdown
# HANDOFF · <项目名>（任何 agent 先读这份）

> 最后更新：YYYY-MM-DD HH:MM · 更新主体：<会话/agent 名>
> 读法：本文件 → `.ai/knowledge/` → 架构文档 → **以代码为最终准**；赶时间先读 §0 快照（目标/状态/下一步），无 §0 的旧文档读 §1/§3/§7；完整接手流程见 intake。描述与代码不符时以代码为准并回来更新本文件。

## ★0. 当前快照（接手者第一眼；每次追加先刷新本节，再追加编年节）

> 只放"当前"，详情指到编年节；本节过期 = 整个交接失真。压缩保全（PreCompact）至少刷新本节 + §3。

- **目标**：<本阶段核心目标，1–2 句>
- **需求与约束**：<用户要求的摘要 + 边界条件；无变更沿用>
- **关键决策**：<影响后续的决策 + 绝对日期 + 一句话理由>
- **状态**：已完成 <概要> · 进行中 <当前工作项> · 阻塞 <卡点，无则写"无">
- **下一步动作**：<按序的具体动作，带文件/命令；完整清单见 §7>
- **相关文件**：<本阶段最相关的 3–5 个路径>
- **关键上下文**：<接手前必须知道的环境/事实/坑>

## ★1. 会话概览
- 会话时间区间（绝对日期）
- 核心目标与交付范围
- 涉及的核心模块与文件范围
- 整体完成度
- 本次沉淀摘要（新增经验 / 决策 / 模式各几条）

## ★2. 已完成工作
按优先级从高到低，每条独立成项：
- `[V]` `src/x/y.ts:42` 做了什么 — 实现要点 — 验证方式与结果（贴命令） — 关联需求/问题号

## ★3. 进行中与断点
每个未完成项给全七件事，缺一项下一个会话就接不上：
1. 工作项名称与优先级
2. 当前完成度与已交付内容
3. **断点具体位置**（文件 + 函数 / 行号）
4. 已完成的前置工作与依赖
5. 暂停原因与阻塞点
6. 接续操作的具体步骤与建议入口
7. 后续预期交付标准

## 4. 已知问题与技术债务
- `[Q]`/`[R]` 现象与复现条件 — 影响范围与风险等级 — 根因初步分析
- 已尝试的方案与结果（含失败的，写清为什么失败）
- 临时规避方案（如有）
- 建议修复方向与前置依赖

## 5. 本次经验沉淀
分四类，每类都问"是否已同步到长期库"，已同步的写索引并转 `[F]`：

### 5.1 问题解决
场景 — 根因分析过程 — 最终方案 — 适用场景与边界 — 参考文件与关键代码位置 — 同步状态

### 5.2 技术决策
决策事项与背景 — 备选方案对比 — 权衡逻辑（收益/成本/风险）— 结论与生效范围 — 约束与注意事项 — 同步状态

### 5.3 可复用代码 / 设计模式
模式名称与功能 — 适用业务场景 — 核心实现逻辑 — 参考路径与使用示例 — 依赖条件与注意事项 — 同步状态

### 5.4 业务规则
规则描述与业务背景 — 约束条件与例外场景 — 对应代码位置 — 变更记录 — 同步状态

## 6. 长期记忆同步说明
- 本次同步进 `.ai/knowledge/` 的内容清单
- 对应的知识库文件路径
- 每条的置信度与适用范围
- 需要后续补全的内容

## ★7. 下一步行动
按优先级：
- `P0` 行动内容与预期目标 — 前置依赖 — 关键风险点 — 建议执行顺序与验证标准

## ★8. 运行与验证
- 环境变量变更说明
- 新增/变更依赖清单与版本
- 服务启动命令与参数
- 模块测试命令与用例范围
- 完整回归验证步骤
- 调试入口与排查工具

## ★9. 操作禁区
- 关键技术决策与设计约束
- **禁止修改的核心文件与模块**
- **禁止变更的接口契约与数据结构**
- 历史踩坑提示与操作红线
- 跨模块协作边界与沟通规则

## 10. 版本记录
每次更新追加一条，倒序排列。**历史条目只追加不修改不删除**：
- YYYY-MM-DD HH:MM · 更新主体 · 核心变更摘要 · 本次沉淀的知识标签
```

★ = 必需节。缺任一必需节即视为交接不完整，下一个会话会出认知断层。
