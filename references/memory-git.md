# 记忆目录 git 化（opt-in）

> 给记忆编辑加**历史与回滚**：谁在什么时候改了哪条记忆、可整体回退。Letta MemFS 同思路。
> 纯 opt-in——部分项目 `.gitignore` 掉 `.ai/` 是有意为之（不入项目仓），本方案是在记忆目录里**另立一个独立 git 仓库**，两者互不干扰。

## 何时启用

- 记忆条目 ≥ 30 条，或曾有"记忆被误改想回滚"的时刻
- 多会话/多 agent 同时写同一记忆库（冲突可查）
- 想把记忆演进作为可复盘资产

## 启用（一次性）

```bash
cd <记忆根>            # 例如 .ai/ 或 memory/
git init -q
git add -A && git commit -m "memory: 基线（启用记忆编辑历史）"
git config user.name  "<主体名>"   # 建议标明是哪个 agent/会话
```

## 日常纪律

- **每次记忆写入会话结束前**：`git add -A && git commit -m "memory: <日期> <一句话变更摘要>"`——与 handoff 收尾同轮做，不单独记
- 提交信息只写变更摘要，**不写密钥**（既有纪律不变）
- 不 push、不设远端（单机审计用；要备份就整目录进你的备份方案）

## 能得到什么

- `git log --oneline` = 记忆演进时间线
- `git diff` = 任意两次同步间的记忆变化
- `git checkout <hash> -- <文件>` = 单条记忆回滚

## 注意

- 独立仓库嵌在项目仓库里时，**必须**把记忆目录加进项目仓 `.gitignore`（多数已在），否则嵌套仓会被父仓当文件夹收录
- 与 Mimosa 之类预写门禁无冲突（git init/add 是普通操作）
- 回滚记忆前先重读现值（宿主内置提取可能已写入了新内容——回滚会覆盖它，二选一要自觉）
