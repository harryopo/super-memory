# 项目文档体系（五方向）

> 接手一个文档不明确的项目、或启动新项目时，按本文件梳理文档体系：**先出地图，确认再建**。
> 五方向是"一个项目该有什么文档"的权威清单；S/M/L 是"做到什么程度"的分档；审计流程是"现在缺什么"的判定方法。
> 配套模板见 `doc-templates.md`；HANDOFF 与长期库的格式仍以 `handoff-template.md` / `knowledge-tiers.md` 为准。

## 一、五个方向

### 方向 1 · 架构与技术栈

**回答**：是什么、由什么构成、为什么这样选。

**必含内容**
1. 项目定位与边界（是什么 / 不是什么 / 一句话架构）
2. 技术栈清单（语言 / 运行时 / 框架 / 关键库 / 数据库 / 部署形态 + 版本 + 包管理器）
3. 系统拓扑（进程 / 容器 / 服务 / 客户端，谁调谁）
4. 分层与模块职责（模块 → 路径 → 职责）
5. 关键数据流（1–2 条端到端链路：请求进入 → 处理 → 落地）
6. 数据模型（表 / 集合 / 关键字段 / 关系）
7. 接口清单（对外 API / 内部 RPC / 事件）
8. 外部依赖与集成点（第三方服务 / 环境变量 / 证书 / 配额）
9. 非功能约束（性能 / 容量 / 安全 / 可用性）
10. 技术决策索引（指向 ADR，主文件不展开）
11. 最后核验 + 代码锚点

**目录层级**
```
.ai/ARCHITECTURE.md           主文件（1–9、11；决策只留索引）
.ai/MAP.md                    目录地图（大项目才建：模块→文件索引，符号名优先于行号）
.ai/knowledge/decisions/      ADR 详版（每决策一篇，K 条目格式）
docs/wiki/01-架构总览.md       对外/新人版（docs 层，受众不同）
docs/wiki/02-决策记录.md       对外版 ADR 摘要
```
**拆分阈值**：ARCHITECTURE > 800 行或模块 > 8 个 → 拆 `docs/wiki/architecture/` 多页，主文件只留索引。

### 方向 2 · 开发规范 / 红线

**回答**：什么绝对不能做、必须怎么做、怎么验证。

**必含内容**
1. 项目身份 + 一句话架构（规则文件顶部 3 行）
2. AI 阅读顺序
3. 硬红线 / 禁止事项（每条可机械检查或判据明确）
4. 权限与审批模型（谁能改什么、什么要确认）
5. 命令速查（构建 / 测试 / 部署 / 启动 / 调试）
6. 编码规范（命名 / 目录 / 错误处理 / 日志 / 类型）
7. 提交与分支规范
8. 验证门禁（lint→类型→测试→集成→回归 + 退出码语义）
9. 尺寸约束（规则文件 ~300 行 / 15 KB，超了迁 docs）
10. 深入文档指针表
11. 踩坑警示（每条配案例）

**目录层级**
```
AGENTS.md / CLAUDE.md             规则文件（受众：本项目 AI；只放硬边界+速查+指针）
.ai/context/coding_standards.md   编码规范详版（含正例反例+机械护栏）
.ai/context/known_issues.md       踩坑库（KI 编号 + 现象/根因/解法）
.ai/knowledge/standards/          验证规范等（K 条目格式）
docs/contributing/testing.md      对外贡献指南
docs/wiki/08-对外口径红线.md       对外口径（如适用）
```
**原则**：红线进规则文件（常驻）；规范细节进 `context/`；案例进 `known_issues`。规则文件不是变更日志。

### 方向 3 · 项目开发文档

**回答**：做什么、给谁用、怎么用。

**必含内容**
1. 产品定位与目标用户（一页纸：是什么 / 给谁 / 不做）
2. 功能清单与优先级（P0 / P1 / P2）
3. 功能规格（做什么 / 不做什么 / 验收标准）
4. 用户故事 / 使用场景
5. 业务规则与领域知识（业务侧，不是技术侧）
6. 界面 / 交互说明（如适用）
7. 接口文档（对外怎么接：curl / SDK / 错误码）
8. 部署与运维（怎么装 / 怎么跑 / 怎么排障）
9. 版本规划

**目录层级**
```
.ai/PROJECT_BRIEF.md          一页纸（是什么/给谁/边界）
docs/wiki/index.md            文档总索引（分层导航）
docs/wiki/00-阅读指南.md       阅读顺序 + 权威层级
docs/wiki/01-项目全景.md
docs/wiki/03-模块索引与改动影响面.md
docs/wiki/04-工具链.md
docs/wiki/09-技术债与规划.md
docs/wiki/domains/*.md        业务领域（大项目才拆）
docs/wiki/modules/*.md        模块说明
docs/wiki/api/*.md            接口文档
docs/DOC-INDEX.md             文档状态索引（五级状态 + 停更横幅 + mtime 警示）
```
**拆分阈值**：单页 > 1500 行 → 切多文件 + 目录索引。

### 方向 4 · 项目进度与控制

**回答**：现在到哪了、下一步是什么、怎么算完成。

**必含内容**
1. 当前状态快照（HANDOFF §0 七槽位）
2. 任务看板（ID / 状态 / 优先级 / 依赖 / 阻塞 / 验收证据）
3. 里程碑与版本规划（ROADMAP）
4. 进度日志（dev-state，追加式）
5. 验证与门禁（VERIFICATION：命令清单 + 基线数字）
6. 发布记录（版本 / 门禁退出码 / 回滚）
7. 交接记录（HANDOFF 编年 + 版本记录）
8. 风险与依赖

**目录层级**
```
.ai/HANDOFF.md               交接 + §0 快照（状态真值）
.ai/TASKS.md                 任务看板
.ai/VERIFICATION.md          验证命令与基线
docs/ROADMAP.md              版本/里程碑规划（追加式，最新节为准）
docs/dev-state.md            进度日志（追加编号，只读最新节）
docs/DOC-INDEX.md            文档状态索引（与方向 3 共用）
```
**跨文件优先级**：状态类以 HANDOFF §0 为准；计划类以 ROADMAP 最新节为准；任务级以 TASKS 为准。冲突时按此裁决并在差异表登记。
**数字防腐**：不写"通过了几项"这类易腐数字，只写脚本汇总行 + 日期；易腐数字必须带测量日期。
**大文件治理**：追加式文件只读最新节 + 顶部指针；超阈值归档到 `docs/archive/`，原文件顶部留指针。

### 方向 5 · AI 协作规范

**回答**：AI 能做什么、不能做什么、怎么交接、多 AI 怎么协作。

**必含内容**
1. AI 唯一入口与阅读顺序
2. 角色与边界（能改 / 要确认 / 绝对禁止）
3. 记忆与文档写入规范（落点、格式、去重）
4. 会话开始/结束协议（intake / handoff 接线）
5. 多 AI 路由（当前接棒、工作区 / branch / HEAD、写锁）
6. 权威层级与冲突裁决（代码 > 规则 > `.ai` > `docs` > 归档）
7. 交接质量要求（§0 七槽位、断点七件事、置信度码）
8. 协作禁区（不改他人候选、不覆盖证据、不擅自 push/发布）

**目录层级**
```
AGENTS.md                        AI 唯一入口（阅读顺序 + 硬约束 + 指针）
CLAUDE.md                        薄导航（只指向 AGENTS，不复述）
.ai/AGENTS.md                    详细协作规范（项目惯例放 .ai/ 时）
.ai/CROSS-AI-HANDOFF.md          多 AI 路由（多 AI 才建）
docs/MULTI-AGENT-WORKFLOW.md     多 Agent 工作流 + 文件锁矩阵（多 AI 才建）
.ai/knowledge/standards/handoff-state.md  交接状态规范
```

## 二、S/M/L 分档

| 档 | 适用 | 必备 | 可选 |
|---|---|---|---|
| **S 最小** | 单人单 AI、个人工具、新项目起步 | ARCHITECTURE（简版）+ 规则文件（AGENTS/CLAUDE）+ PROJECT_BRIEF + HANDOFF + TASKS | VERIFICATION、DECISIONS |
| **M 标准** | 单人或小团队、有交付压力 | S + DECISIONS + MAP + DOC-INDEX + ROADMAP + VERIFICATION + context/coding_standards | docs/wiki 页面族 |
| **L 完整** | 多 AI / 多会话 / 多人 | M + CROSS-AI-HANDOFF + MULTI-AGENT-WORKFLOW + knowledge 分类齐 + docs/wiki 全套 | 锁矩阵、审计目录 |

**判档三问**：会话是单会话还是多会话并行？协作者是否 > 1？是否多工作区 / 多 branch 同时推进？任一为"多"→ 升档。

## 三、文档体系审计（接手时文档不明确才走）

**前置**：先按 `intake-memory-discovery.md` 探测到全部现有文档（含非标准命名）。

**四步**
1. **扫描**：列出项目内全部 `.md`（排除 node_modules/.git/第三方），按 `DOC-INDEX` 五级状态归类：现役准绳 / 活文档 / 停更 / 历史快照 / 索引元文档。
2. **映射**：把每份文档归到五方向之一（或"未归类"）；同一方向多份 → 标"重复候选"。
3. **判定缺失**：按分档矩阵对照——S 档缺哪几件、M/L 档还缺什么。逐项标：已有 / 缺失 / 重复 / 过期（最后核验 > 90 天或内容与代码不符）/ 无索引。
4. **出地图**：输出下表给用户，**确认后才建骨架**：

```
方向          已有                     缺失           重复/过期       建议
架构与技术栈   .ai/ARCHITECTURE.md ✓   MAP.md          —              建 MAP（模块 9 个）
开发规范红线   CLAUDE.md（8 行）         context/…      —              先补红线 5 条
项目开发文档   docs/wiki/index.md      DOC-INDEX      2 份架构重复   合并+建索引
进度与控制     HANDOFF.md ✓            ROADMAP        —              建 ROADMAP
AI 协作规范    AGENTS.md ✓             —              —              保持
→ 建议档位：M（缺口 4 件）；确认后按模板建骨架，已有文件只补缺失节不重写
```

**纪律**
- 审计只读：不改、不删、不移动任何现有文档
- 缺失项只报"缺什么 + 建议建什么"，**不补写内容**（内容要真实会话产出）
- 重复项按 `knowledge-tiers.md` 四操作合并；涉及删除/隔离走 `neat` 第 2.5 步
- 新建骨架遵循"标题 + 一行用途 + 占位符"，不预铺空分类空子目录（与 `intake-scaffold.md` 同原则）

## 四、与现有文档的关系

| 现有件 | 在五方向中的位置 |
|---|---|
| `.ai/HANDOFF.md`（十一节） | 方向 4 的状态真值 + 方向 5 的交接协议 |
| `.ai/knowledge/`（五分类） | 方向 1 的 decisions、方向 2 的 standards |
| `AGENTS.md` / `CLAUDE.md` | 方向 2 的红线 + 方向 5 的唯一入口 |
| `docs/wiki/` | 方向 3 的对外文档层 |
| `.learnings/` | 不属于五方向（实时暂存，见 capture） |
| 宿主记忆库 | 不属于五方向（跨项目偏好，见 save） |
