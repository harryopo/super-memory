# 三层知识与编辑判据

neat 的理论层。操作流程里要用到的判据已写进 neat 正文，本文件放完整版与反例表。

## 三类知识，三种受众

| 位置 | 受众 | 职责 | 不同步的代价 |
|---|---|---|---|
| agent 记忆库 | agent 自己跨会话复用 | 偏好、非显而易见的项目事实、reference | 下次会话忘记历史决策 |
| 项目根规则文件 | 当前项目里的 AI | 约定、结构、红线、命令速查 | 下次 AI 在这个项目里走弯路 |
| `docs/` + `README.md` | **别人**（同事、下游、接手的 AI） | 接入指南、架构图、运维手册、交接 | 别人根本没法正确接入或运维 |

受众不同、职责不重叠：规则文件里写"新增了 5 个路由" ≠ docs 里"下游怎么接这 5 个路由"——前者提醒自己，后者教别人，**两份都要写**。只写一层就是漏。

代码可以随时重写，但文档和记忆是跨会话、跨 agent 的唯一桥梁。记忆里留着过期信息，下一个 agent 就会基于错误前提做决策。

## 规则文件是规则手册，不是变更日志

最常见的翻车：每次开发完在规则文件顶部加一段"2026-05-08 X 上线，详见 docs/Y.md"。一次很爽，半年后顶部堆了 200 行叙事，把真正的规则挤到看不见——而超尺寸的规则文件会让下次会话的 AI 根本看不到重要规则。

判断标准只有一条：**下次 AI 写代码时如果没看到这条，会不会犯错？**

| 例子 | 进规则文件？ | 理由 |
|---|---|---|
| "Prisma 查询只写在 `modules/**/data/`" | 进 | 违反就是边界破坏，AI 必须看到 |
| "rsync 单文件部署必须用完整 target 路径" | 进 | 踩坑警示，不写就会再踩 |
| "禁止裸跑 systemctl stop worker" | 进 | 事故级红线 |
| "环境变量清单 / 部署命令速查" | 进 | 每次都要用 |
| "2026-05-08 timelineAt 上线，详见 docs §5.4" | 不进 | 详细机制在 docs，改到这块自然会读 |
| "2026-04-30 起公网开放，匿名可访 /、/all" | 不进 | 事实归 architecture，概览一句话足矣 |
| "5/8 修了 X bug 的复盘细节" | 不进 | 单次事故记忆，归 memory 或直接隔离 |
| "详见 docs/Z.md" 的指针句 | 不进 | 这个角色已被「深入文档」指针表占掉 |

**该进**：硬边界、禁止事项、命令速查、权限模型、协作流程、深入文档指针表、踩坑警示。
**不该进**：历史叙事、详细机制说明、单次事故复盘、bug fix 流水账。

叙事的归宿是 git log、项目的变更记录页或 `docs/CHANGES.md`，不是规则文件顶部。
